# 原程序改造说明

## 保持不变

- 外部 `model/best.pt` 加载方式。
- Ultralytics `model.predict()` 的置信度、推理尺寸和类别参数。
- 选择距画面中心最近目标的逻辑。
- 检测框中心整数化顺序。
- X 右正、Y 上正的误差公式。
- `[x,y]\n` 串口格式。
- `[9999,9999]\n` 目标丢失语义。
- 默认 30 Hz 与目标出现/消失立即发送。
- MJPG、640×480、摄像头缓冲 1 帧。

## 模块化结果

| 原程序职责 | 新模块 |
|---|---|
| 全局常量 | `config/settings.json` + `config_manager.py` |
| 模型与摄像头循环 | `vision_worker.py` |
| 最近目标与误差 | `vision_core.py` |
| 串口打开和发送 | `serial_manager.py` |
| 协议格式 | `protocol.py` |
| `BASE_DIR` 路径 | `resource_path.py` |
| OpenCV 窗口和终端输出 | `main_window.py` |

## 线程设计

- Qt 主线程只创建控件、处理用户输入、显示 QImage、更新状态与日志。
- `VisionWorker` 移入 `QThread`；其 QTimer 每次处理一帧，单次推理结束后把控制权交回线程事件循环。
- 串口限频 QTimer 位于主线程，但不执行持续循环；只写一个很短的 ASCII 帧。
- 窗口关闭时使用阻塞队列调用在视觉线程内部释放摄像头，然后退出并等待线程。

## 新增安全行为

- “识别”和“发送”完全分开。
- 暂停发送、停止识别与急停都不会沿用旧误差。
- 串口失败不会终止视觉线程。
- 摄像头连续失败会停止识别、释放设备并保留主界面供用户重开。
- 配置损坏回退默认值，不导致程序退出。
- 模型切换在识别运行时被拒绝，避免跨帧状态混乱。
